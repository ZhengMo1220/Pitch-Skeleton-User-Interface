# 硬體資源評估報告

用於評估本系統的硬體需求，作為主機 / 筆電 / GB10 選型與多相機擴充規劃的依據。

**最後更新**：2026-09-22

---

## 一、結論摘要

| 問題 | 答案 |
|---|---|
| 顯存夠不夠？ | **完全不是瓶頸**。8 路推估僅需約 2.9 GB，24 GB 的 4090 綽綽有餘 |
| 能否 5 路即時分析？ | **不行**。5 路共卡循序處理，每路僅約 8.8 FPS（相機原生 179 FPS） |
| 那該怎麼辦？ | **本系統架構本來就是「即時擷取、離線分析」分離**，不需要即時分析 5 路 |
| 真正該評估的瓶頸是什麼？ | **5 路即時錄影**的 CPU、磁碟寫入與介面頻寬 —— 這部分尚未實測 |

---

## 二、實測數據

**測試環境**

| 項目 | 規格 |
|---|---|
| GPU | NVIDIA GeForce RTX 4090（24 GB，128 SM） |
| 環境 | conda `Pitcher`，Python 3.8.20，PyTorch 2.0.1 + CUDA 11.8 |
| 測試輸入 | 1920×1084 合成影像（與相機實際解析度相同） |
| 推論路徑 | 現行架構（mmdet 人物偵測 + mmpose ViTPose 姿態估測） |
| 測試方式 | 暖機 3 幀後，計時 20 幀取平均 |

**單路（一支相機）結果**

| 項目 | 數值 |
|---|---|
| 模型載入耗時 | 4.9 秒 |
| 模型權重佔用 GPU | 791 MiB |
| 推論額外佔用 GPU | 270 MiB |
| **單路 GPU 合計** | **1,061 MiB（約 1.0 GB）** |
| 系統記憶體（本行程 RSS） | 約 786 MiB |
| **推論速度** | **44.1 FPS（每幀 22.7 ms）** |

**多相機顯存推估**

模型權重可共用，推論緩衝各路獨立，故推估公式為 `791 + 270 × N` MiB：

| 路數 | 預估顯存 |
|---|---|
| 2 路 | 1.3 GB |
| 3 路 | 1.6 GB |
| 5 路 | 2.1 GB |
| 8 路 | 2.9 GB |

## 三、關鍵發現與解讀

### 顯存不是瓶頸，運算速度才是

8 路推估僅 2.9 GB，連 8 GB 顯存的筆電顯卡都裝得下。但速度的落差很大：

- 單路推論 44 FPS
- 相機原生 179 FPS
- 5 路共用一張卡循序處理 → 每路約 8.8 FPS

對投球這種高速動作而言，8.8 FPS 完全不足以做即時分析。

### 但這不構成問題 —— 因為架構本來就不打算即時分析

學姊論文明確記載系統採「**即時擷取與離線分析分離**」的設計：

> 「由於投球分析涉及相機校正、人體姿態估測、三維人體骨架重建及生物力學參數計算等多項運算，若直接於 Live 模式執行將影響即時擷取效能，因此本研究採用即時擷取與離線分析分離之架構。」

即時階段只負責**錄影存檔**，分析在 Replay 模式離線進行。因此：

- **即時階段的瓶頸**：CPU（影像編碼）、磁碟寫入頻寬、USB/網路傳輸頻寬 —— 幾乎不吃 GPU
- **離線階段的瓶頸**：GPU 算力 —— 但可以慢慢跑，不需要即時

**本次量測的是離線分析階段的 GPU 消耗，不是即時錄影階段的資源消耗。** 兩者瓶頸完全不同，不可混為一談。

## 四、硬體選型建議

| 用途 | 主要瓶頸 | RTX 4090 主機 | 筆電 | GB10 |
|---|---|---|---|---|
| 5 路即時錄影 | CPU / 磁碟 / 介面頻寬 | 適合 | 視規格而定 | 規劃用途，適合 |
| 離線骨架分析 | GPU 算力 | 適合（主力） | 可行但慢 | 不建議（需重建整套 ARM64 環境） |

**目前規劃**（2026-09-21 確認）：GB10 僅作 5 路畫面監看，分析主力維持 Windows + RTX 4090。此規劃與上述數據一致。

---

## 五、尚未量測的項目

以下數據對完整評估有價值，但需要額外條件才能取得：

| 項目 | 需要什麼 | 用途 |
|---|---|---|
| 5 路即時錄影的 CPU / 磁碟寫入速率 | 實際接上多台相機錄影 | **這才是即時階段的真正瓶頸**，決定主機規格 |
| 完整分析一支影片的總耗時 | 可直接測（例：170 幀影片） | 估算「一場訓練 50 球要分析多久」 |
| RTX 5090 的效益 | 實機 | 目前僅能給理論推估值 |
| 多路並行（非循序）的實際吞吐 | 改寫測試腳本 | 現行程式為循序處理，若改並行可能提升 |

## 附錄：量測方法

量測腳本置於暫存目錄（非專案檔案），邏輯為：

1. 記錄基準線（載入任何模型前的 GPU / RAM 用量）
2. 載入 `utils.model.Model`，記錄模型權重佔用
3. 建立 `PoseEstimater` 並啟用偵測
4. 以 1920×1084 合成影像暖機 3 幀，再計時 20 幀
5. 以 `nvidia-smi` 讀取整卡用量、`psutil` 讀取本行程 RSS、`torch.cuda.memory_allocated/reserved` 讀取 PyTorch 配置量

若需重現，可請 AI 助手依此邏輯重新產生腳本。
